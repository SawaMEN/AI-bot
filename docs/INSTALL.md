# AI-bot — установка, первая настройка и проверка

**Начните с [пошаговой инструкции для новичка](QUICKSTART.md).** Она объясняет, что такое сообщество ВК, где взять ID и токен, как включить Long Poll и добавить бота в беседу.

Поддерживаются Debian 12+ и Ubuntu 22.04+, systemd и Linux amd64/arm64. Python на сервере не требуется. На VDS 1 vCPU и 1 ГБ RAM большая локальная модель не нужна: запросы отправляются внешнему бесплатному API.

## Установка и обновление

    curl -fsSL https://raw.githubusercontent.com/SawaMEN/AI-bot/main/install.sh | sudo bash

Если мастер не запустился из-за отсутствия терминала, выполните:

    sudo aibot setup

После повторной установки данные и настройки в /var/lib/ai-bot и /etc/ai-bot сохраняются. Запуск службы:

    sudo systemctl status ai-bot
    sudo aibot menu     # удобное меню: ✓ ВКЛ / ✗ ВЫКЛ
    sudo aibot guide    # где найти ID, токен и разрешения ВК
    sudo aibot next     # что осталось настроить?
    sudo aibot doctor   # статусы и причины ошибок
    sudo aibot logs     # журнал ошибок

## Разрешения ВКонтакте — не путайте страницу и беседу

**Сообщество ВК** (страница группы или паблика) — имя, от которого отвечает AI-bot. **Беседа ВК** — групповой чат с участниками, куда вы добавляете это сообщество.

Порядок: создать сообщество → найти числовой ID → получить токен с доступом к сообщениям → включить «Сообщения сообщества» и Long Poll (`message_new` и `message_event`) → добавить сообщество в беседу и разрешить чтение сообщений.

**Где именно найти каждый пункт, с примерами:** [QUICKSTART.md](QUICKSTART.md). Те же инструкции выводит команда `sudo aibot guide`. В меню пункт 10 показывает инструкцию, а пункт 11 — следующий шаг. Настройки событий можно попробовать включить в пункте 9.

## Бесплатные API

В меню sudo aibot выберите провайдера, вставьте API-ключ бесплатного аккаунта и включите «Автоматический подбор подтверждённых бесплатных моделей». Можно подключить несколько ИИ, а участники смогут выбирать разрешённые модели через кнопки ВК. Если основная модель недоступна, бот может попробовать ещё одну бесплатную (эту функцию можно запретить на сервере, в беседе или лично).

Важно: не подключайте банковскую карту и платный биллинг. Изменения тарифов у провайдеров не контролируются ботом.

## Выбор: терминал или веб-панель с HTTPS

**Самый простой и безопасный вариант** — терминал: `sudo aibot menu`. Публичные порты не нужны.

Если нужен постоянный веб-доступ, откройте в меню пункт 8. Для собственного домена нужны A-запись DNS на IP VDS, свободные порты 80/443 и Caddy. Команда: `sudo aibot panel setup bot.example.com`. Логин и пароль появятся после установки. **Если VPN занимает порт 443, AI-bot не трогает его:** оставайтесь в терминале или используйте SSH-панель.

Для временной панели по SSH создайте на своём компьютере туннель:

`ssh -L 8765:127.0.0.1:8765 USER@SERVER_IP`

На VDS запустите `sudo aibot web`, затем откройте на компьютере `http://127.0.0.1:8765`. Логин `admin`, пароль будет показан в терминале. Закрыть: Ctrl+C.

## Диагностика

    sudo aibot doctor
    sudo journalctl -u ai-bot -n 60 --no-pager

Проверяются база SQLite, бесплатные модели, доступ к ВК, разрешения message_new и message_event. Проверка не отправляет платных генераций. Реальную работу внешних API и отправку сообщений ВК нужно дополнительно проверить с действующими ключами.

## Миграция и откат

Go читает старые конфигурации Python и сохраняет существующие SQLite-таблицы. При сохранении конфигурации Python v1 создаётся защищённая резервная копия `/etc/ai-bot/config.json.python-v1.bak`. Старый платный Custom API автоматически не включается. Архивная версия Python сохранена в ветке `archive/python-last-main` и в истории Git. После установки Go проверьте доступность сервиса через `sudo aibot doctor` и реальные сообщения в ВК.

## Приватность

История сообщений (по умолчанию 7 дней) хранится в SQLite, а фрагменты контекста отправляются выбранному ИИ. При резерве история может отправиться второму ИИ. Уведомите об этом всех участников беседы. В конфиденциальных беседах рекомендуется отключить резерв и AI Horde, где данные могут обрабатываться на волонтёрских машинах.

Входящие события и очередь необработанных запросов сохраняются между перезапусками. Применяются отдельные лимиты вызовов API для сервера, пользователя и диалога. Включение большего количества бесплатных API не отменяет их индивидуальных квот.
